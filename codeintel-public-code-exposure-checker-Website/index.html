A Simulated Search

The tool identifies code snippets and sensitive data in publicly exposed code. The data named in the README is API keys, database credentials, and internal IP addresses.

The search itself is simulated. The programme analyses a fixed set of example results. It does not call a search engine API. The findings are the same whatever search term is given. That limit is printed here at the same size as the claim, not in a footnote.

The Five Fixed Results

The fixed set holds five example results. Result one holds an example API key entry. Result two holds a database password entry. Result three holds an internal IP address in a private range. Result four holds no sensitive data. Result five holds a second example API key entry and a second internal address in a private range. No found value is reproduced on this page; the categories are the record.

Same Findings for Every Term

The search term changes none of these five lines. A reader must not treat the printed findings as findings about the term they typed.

What the Patterns Extract

The analysis is the real part of the tool. Three patterns do the work. One pattern reads API key assignments. One pattern reads database password assignments. One pattern reads IP addresses in dotted form. Matches are gathered in three lists. Each list is sorted. Each list holds each value once. The sorted order is deliberate: two runs over the same set print their findings in the same order.

Endings at 0 and at 1

The README records the verified behaviour in one point. A run with a search term prints the simulated findings: example API keys, a database credential, and example IP addresses. The run exits 0.

Code facts beside that point. A run that finds exposure still ends at 0. Only a failed save or an unexpected error ends at 1. The exit code therefore says nothing about what was found.

Found Values Enter the Log in Full

Found values are written into the log in full. A log file from a run holds those values, and it must be handled as a file that holds them. This page reproduces no found value.

Saving

Saving happens only when an output file was named and findings exist. The saved file has three headed sections: API Keys, Database Credentials, and IP Addresses. Each found value is written as one dashed line under its heading. A failed save ends the run at 1.

The README as printed

# codeintel-Public-Code-Exposure-Checker
Identifies code snippets and sensitive data (API keys, database credentials, internal IP addresses) accidentally exposed on public websites or repositories. The search itself is simulated: the program analyses a fixed set of example results, it does not call a search engine API, so the findings are the same whatever search term is given. Focused on tools for static code analysis, vulnerability scanning, and code quality assurance.

## Install
`git clone https://github.com/ShadowGuard-AI/codeintel-public-code-exposure-checker`

## Usage
`python3 main.py SEARCH_TERM [-o OUTPUT] [-v]`

## Parameters
- `-h`: Show help message and exit
- `search_term`: The search term to use (for example 'API_KEY in:github'). Use Google Dorks.
- `-o`, `--output`: Output file to save results (optional).
- `-v`, `--verbose`: Enable verbose logging (debug level).

## Verified behavior
- Running with a search term prints the simulated findings (example API keys, a database credential, and example IP addresses) and exits 0. Do not treat these example findings as results for the search term given.
